# 主题系统设计文档

日期：2026-09-23
状态：已与用户确认

## 1. 背景

界面第一版能跑，但「平平无奇」：强调色是 `#5274f5` 蓝紫配渐变图标，属于生成式设计最典型的指纹；全站只有 14px 与 16px 两个字号，标题在视觉上压不住正文；所有过渡都是 `0.12s`，没有任何 `:active` 按压反馈，也没有 `:focus-visible` 焦点环（键盘操作时看不到焦点）；任务卡片是「边框 + 白底 + 圆角」这种可以套在任何应用上的通用做法。

把这些直接改死成某一种风格是错的：那等于把作者的口味强加给使用者，以后想换还得改代码。正确的做法是让视觉变成**数据**——主题可切换、可自定义。

## 2. 目标与非目标

### 2.1 目标

1. 主题以 CSS 文件形式存在，可切换、可自定义、可随数据一起备份。
2. 明暗模式与主题选择是两个互不干扰的维度。
3. 把现有一千行样式里的硬编码值提取成变量，主题只需覆盖关心的部分。
4. 内置若干套差异明显的主题，其中包含「纸本便签」。
5. 顺手修掉第 1 节列出的五个设计问题（改在默认主题里，不改结构）。

### 2.2 非目标

- 不做主题在线市场、不做导入导出按钮（用户把文件放进目录即可）。
- 不允许主题改写布局结构（只开放变量，不开放选择器自由发挥）。主题文件里的选择器由约定的变量块承载。
- 不做主题预览缩略图。
- 不改动任何现有功能行为。

## 3. 概念模型

### 3.1 两个正交维度

| 维度 | 取值 | 落到根元素 | 作用 |
| --- | --- | --- | --- |
| 明暗模式 | `light` / `dark` / `system` | `data-appearance="light" \| "dark"` | 决定用主题里的哪一套颜色 |
| 主题 | 任意主题 id | `data-theme="<id>"` | 决定视觉语言 |

一个主题文件**可以同时定义明暗两套**，也可以只写一套。只写一套时，另一种模式沿用同一套颜色，由使用者自己负责。

### 3.2 主题标识

- id：文件名去掉 `.css`，只保留字母数字（Unicode 感知，中文可用）与 `-`、`_`；清空后回退 `theme`。
- 名称：文件首行的 `/* @name 纸本便签 */`；没有该注释时用文件名。
- 同名时自定义主题覆盖内置主题，设置面板标注来源。

## 4. 主题文件格式

```css
/* @name 纸本便签 */

:root[data-theme="paper"] {
  --bg: #fbf9f4;
  --surface: #ffffff;
  --text: #1f1b16;
  --accent: #b23a2f;
  /* 其余变量省略则沿用默认值 */
}

:root[data-theme="paper"][data-appearance="dark"] {
  --bg: #17140f;
  --surface: #1e1a14;
  --text: #ebe5da;
}
```

约定：

- 每个变量块必须以 `:root[data-theme="<自己的 id>"]` 开头，可选的暗黑块再加 `[data-appearance="dark"]`。
- 只允许声明自定义属性（`--*`），不允许写影响结构的规则。加载时会做一次过滤：只保留变量声明块，丢弃其它规则，避免主题文件改坏布局。
- 变量有默认值，主题只需覆盖想改的。

## 5. 变量契约

### 5.1 核心颜色（主题通常都要给）

| 变量 | 用途 |
| --- | --- |
| `--bg` | 窗口底色 |
| `--surface` | 卡片、面板表面 |
| `--surface-soft` | 次级表面：悬停、输入框 |
| `--sidebar` | 侧栏底色 |
| `--border` / `--border-strong` | 分隔线与控件描边 |
| `--text` / `--text-soft` / `--text-faint` | 三级文字 |
| `--accent` / `--accent-soft` | 强调色与其浅色底 |
| `--danger` / `--danger-soft` | 危险操作 |
| `--warn` | 警告 |
| `--scrim` | 遮罩层 |

### 5.2 可选（有默认值）

- 字体：`--font-body`、`--font-display`、`--font-mono`
- 字号：`--text-xs` … `--text-xl`
- 形状：`--radius-sm`、`--radius-md`、`--radius-lg`、`--radius-pill`
- 阴影：`--shadow-soft`、`--shadow-panel`
- 动效：`--duration-fast`、`--duration-base`、`--ease-out`

间距不开放为变量：主题极少改间距，开放它只会让变量表变长。

## 6. 加载与切换

### 6.1 来源

| 来源 | 位置 | 读取方式 |
| --- | --- | --- |
| 内置 | `src/themes/*.css` | 随前端资源打包，`fetch` 读取 |
| 自定义 | `<数据目录>/themes/*.css` | Rust 命令读取并返回文本 |

内置主题的文件名在 `theme.js` 里硬编码成一张清单：Tauri 的静态资源服务不提供目录列表，前端无法枚举 `src/themes/` 下的文件。新增内置主题需要同时改这张清单，这是刻意接受的代价。

### 6.2 命令

| 命令 | 入参 | 返回 |
| --- | --- | --- |
| `list_user_themes` | 无 | `[{ id, name, css, file }]` |
| `seed_builtin_themes` | `[{ fileName, css }]` | 实际写入的文件名列表；已存在的文件一律跳过 |
| `open_themes_dir` | 无 | 在数据目录下创建 `themes/` 并用文件管理器打开 |

### 6.3 应用方式

前端在 `<head>` 里维护一个固定的 `<style id="theme-vars">`，切换主题时只替换它的文本内容并更新根元素属性，**不重建 DOM**（此前几轮已经因为全量重建踩过动画重播、焦点丢失、点击被吃掉三个坑）。

设置面板提供「重新加载主题」，改完 CSS 目录里的文件不用重启程序。

### 6.4 内置主题预置

启动加载主题时，前端按 id 比对内置清单与数据目录里的文件，缺哪套就把内置文件的**原文**（含 `@name` 注释，否则写出去的副本显示名会退化成文件名）经 `seed_builtin_themes` 写进 `<数据目录>/themes/`。写入用 `create_new`，已存在的文件一律不碰：数据目录里那一份是用户能直接编辑的版本，比内置的新旧更该保留。

文件名由前端给出，因此后端只接受单层、`.css` 结尾、不含路径分隔符、不以点开头的名字，`..\` 这类名字在落盘前就被丢掉。

预置之后，同名文件在合并时覆盖内置版本，设置面板里标注为「自定义」。好处是改主题只要改数据目录里的文件再点「重新加载主题」，不必重新构建程序；代价是程序内置的那份从此被遮蔽，改 `src/themes/` 不再影响界面。

`default` 没有文件（它的取值来自 `style.css` 的默认值），不参与预置，也就无法通过数据目录改写。

## 7. 兼容性

- `settings.theme` 语义不变（`light` / `dark` / `system`），老数据直接可用。
- 新增 `settings.themeName`，缺省 `default`；文件缺失时回退到 `default` 并给出提示。
- 主题目录不存在时自动创建，不报错。

## 9. 测试策略

### 9.1 Rust

- 文件名到 id 的规范化（大小写、非法字符、空名）。
- 首行 `@name` 注释解析，缺失时回退文件名。
- 主题目录不存在时自动创建。
- 目录里混入非 CSS 文件时忽略。
- 预置：缺失的文件写出来、已存在的原样保留、`..\`／非 `.css`／点开头的文件名被拒、中文文件名可写、空清单不建目录。

### 9.2 前端（`node --test`）

- 主题 CSS 过滤：只保留 `:root[data-theme=...]` 变量块，丢弃其它规则（含 `body { display:none }` 这类恶意/误写的规则）。
- 明暗解析：`system` 跟随 `prefers-color-scheme`。
- 主题回退：`themeName` 指向不存在的主题时用 `default`。
- 预置种子：只挑数据目录里没有的、带文件的内置主题，且保留原文（`@name` 不能丢）；读不到的内置主题不进种子。

### 9.3 手动验收

1. 设置里切三套主题，界面立刻变化且不闪烁、不重建。
2. 往 `<数据目录>/themes/` 放一个自写 CSS，点「重新加载主题」后出现在列表里并可选中。
3. 明亮 / 暗黑 / 跟随系统三态切换正常，主题的自带暗黑变体生效。
4. 删除主题文件后选中它，回退到 `default` 并提示。
5. 键盘 Tab 走到每个可交互元素都有可见焦点环。

## 10. 实施顺序

1. `style.css` 全量变量化：颜色、字体、字号、圆角、阴影、动效改为 `var(...)`，并补上 `:active` 与 `:focus-visible`。
2. 写三套内置主题文件。
3. Rust：`list_user_themes`、`open_themes_dir` 与对应单测。
4. 前端：`theme.js` 扩展为「加载 + 过滤 + 应用」。
5. 设置面板：主题列表、重新加载、打开主题目录。
6. 存储：`themeName` 字段与回退逻辑。
7. 构建、验证、提交。
