# sticky-todo 到期、提醒与重复设计文档

日期：2026-09-29
状态：已与用户确认

## 1. 背景与目标

到这一版为止，任务只有「创建时间」与「更新时间」，没有时间维度的语义：没有到期日，没有提醒，也没有重复。原设计文档（2026-09-23）把「提醒通知、周期性重复任务」明确列为非目标；本设计有意推翻这一条，属于产品转向，不是补漏。

### 目标

1. 任务可以设置到期时间，精确到分钟。
2. 任务可以设置重复规则，完成后自动生成下一次。
3. 左栏给出「今天 / 逾期 / 本周」三个视图，并带未完成计数。
4. 进程活着（含隐藏到托盘）时，到点发系统通知。

### 非目标

- 不做自然语言日期解析（「明天下午三点」）。
- 不做日历视图、不做甘特图、不做周回顾统计。
- 不做完整 RRULE 语法（不解析 `FREQ=MONTHLY;BYDAY=-1FR` 这类规则）。
- 不做「每周起始日可配置」，固定周一。
- 不做重复任务的历史统计与连续打卡。
- 不做退出程序后的提醒（不写系统计划任务）。

## 2. 数据模型与版本

任务新增两个字段：

```json
{
  "dueAt": "2026-09-30T01:00:00.000Z",
  "repeat": "every:3:day"
}
```

- `dueAt`：UTC ISO8601 字符串，与 `createdAt` 同一套约定，展示时转本地时间；`null` 表示没有到期时间。
- `repeat`：`null`（不重复）、`daily`、`weekly`、`monthly`、`weekdays`（周一至周五）、`every:N:day`、`every:N:week`、`every:N:month`（N 为正整数）。
- 重复必须挂在到期时间上：没有 `dueAt` 时 `repeat` 不生效，界面上重复选项也禁用（清空到期时间时一并清空重复）。

### 数据文件版本

`CURRENT_VERSION` 由 1 升到 3：

| 版本 | 含义 | 读取时 |
| --- | --- | --- |
| 1 | 无时间字段的旧版 | 升到 3 |
| 2 | 标签时代（`tags` 字段） | 无标签内容则降级到 3；有标签内容仍拒绝写入 |
| 3 | 当前（`dueAt` / `repeat`） | 原样读取 |
| >3 | 更新版本写的 | 拒绝打开 |

Rust 的 `Task` 是强类型、没有字段透传，必须补上 `due_at` 与 `repeat`，否则前端写入的到期时间会在后端读写一轮后被静默丢掉（1.2.0 的标签字段就是这么丢的）。

**副作用（用户已知悉）**：升到 3 之后，1.4.1 及更早的程序会拒绝打开数据文件。数据目录在多台机器间同步时，各台都要升级。

## 3. 投影与视图

### 视图种类

`group`（分组，默认）、`all`（全部待办）、`today`（今天）、`overdue`（逾期）、`week`（本周）。

- `today`：`dueAt` 落在本地今天（00:00:00 至 23:59:59）。
- `overdue`：`dueAt` 早于当前时刻 **且未完成**；已完成的任务不算逾期。
- `week`：`dueAt` 落在本周（本地周一 00:00 到下周一 00:00）。

`hideCompleted`、`completedBottom` 在三个新视图里与既有视图一致地生效。

### 排序

- 聚合视图（`all` / `today` / `overdue` / `week`）：按 `dueAt` 升序，没有 `dueAt` 的排在后面并按原有 `order`、`createdAt` 排序。
- 分组视图：保持现有的手动顺序（`order`），否则上移／下移立刻失去意义。

### 接口

- `resolveView(ui)` 接受五种 kind，非法取值回落到 `group`。
- `visibleTasks(state, view, query)` 支持新 kind；返回值形状不变（`{ task, groupName }`）。
- 新增纯函数 `isOverdue(task, now)`、`isDueToday(task, now)`、`isDueThisWeek(task, now)`、`nextDueAt(dueAt, repeat, now)`。
- `buildView` 的 `viewItems` 扩展为四项，每项带未完成计数：全部待办 / 今天 / 逾期 / 本周。
- `flatTitle` 对应四个标题。

## 4. 界面

- 左栏固定视图四项，各带未完成计数；当前项高亮规则不变。
- 任务行显示到期徽章：`09-30 09:00`；已过期的用危险色；已完成任务的徽章淡化。
- 工具区新增日历按钮，点击在行内展开「到期与重复」面板：
  - `input[type=date]`、`input[type=time]`（新建时默认 09:00）
  - 重复下拉：不重复 / 每天 / 每个工作日 / 每周 / 每月 / 每 N 天 / 每 N 周 / 每 N 月，选自定义时出现数字输入
  - 「清除」按钮：清空到期时间与重复
  - `Enter` 保存、`Esc` 收起；交互与输入框焦点恢复沿用标签输入行那套做法
- 没有到期时间时重复下拉禁用，并提示「先设置到期时间」。

## 5. 提醒

- 新增依赖 `tauri-plugin-notification`，capabilities 里加上通知权限。
- 前端在数据变化时把提醒计划推给后端：`set_reminders([{ id, dueAt, text }])`，内容为「未完成 + 有到期时间」的任务。
- 后端常驻线程每 30 秒比对一次计划，到点调用系统通知。去重键是 `(id, dueAt)`，同一到期时间只响一次。
- 启动后的补提醒有窗口限制：只提醒 24 小时内到期的，避免开机炸出一堆历史逾期。
- 托盘 tooltip 显示摘要，例如「逾期 1 · 今天 2」。
- 通知点击行为不额外定制。

## 6. 重复

勾选完成（未完成 → 已完成）时，若任务有 `repeat` 且有 `dueAt`：

1. 按规则推进到期时间，必要时**循环推进直到晚于当前时刻**（避免生成出来的下一条已经过期）。
2. 新建一条未完成任务：新 id、复制正文与图片、`groupId` 不变、`dueAt` 用新值、`repeat` 沿用、`createdAt` 取当时时间、`order` 排在该分组末尾。
3. 原任务保持已完成，留作记录。

规则细节：`monthly` 遇到当月没有该日期时取当月最后一天；`weekdays` 跳过周六周日；`every:N:month` 与 `monthly` 同样处理月末。

取消勾选不会回收已生成的下一条。

## 7. 测试策略

### 7.1 前端单元测试

- 视图筛选边界：`dueAt` 正好是今天 00:00、23:59、明天 00:00；跨周边界（周日 23:59 与下周一 00:00）。
- 逾期只算未完成任务。
- 聚合视图的到期排序：有到期在前、升序，无到期按 order 跟在后面。
- 分组视图仍按手动 order 排。
- `nextDueAt`：五种基础规则、`every:N:*`、月末（1 月 31 日 + 每月）、工作日跨周末、循环推进跳过多个周期。
- `viewItems` 的计数正确（只算未完成）。

### 7.2 Rust 单元测试

- `Task` 的 `dueAt` / `repeat` 往返保留（防字段再被丢掉）。
- 版本 1 / 2 / 3 文件都能读到版本 3；版本 2 带标签内容仍拒绝；版本 4 仍拒绝。
- 提醒计划解析、去重键生成、24 小时补提醒窗口的判定。

### 7.3 手动与端到端

- 左栏四个视图的切换与计数；徽章颜色；到期面板的输入与清除。
- 完成一条重复任务后，新任务出现在列表里，到期时间推进正确。
- 真实应用：建一条 1 分钟后到期的任务，等系统通知弹出（Windows 通知中心可见）。
- 旧数据文件（版本 1）打开后能正常读写，并升级为版本 3。
