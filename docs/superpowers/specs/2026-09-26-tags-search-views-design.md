# sticky-todo 标签、搜索与视图设计文档

日期：2026-09-26
状态：已与用户确认

## 1. 背景

`sticky-todo` 目前只有「分组」一个组织维度。任务数量上去之后，两个场景无解：一是「我记得记过这件事，但想不起放在哪个分组」，二是「把同一件事的相关条目找齐」。本设计为任务增加标签字段，把搜索与标签筛选做成跨分组的视图，并把「分组」降为视图列表中的一项。

这一版还要顺带修一个已存在的隐患：`src-tauri/src/store.rs` 里的 `Task` 是强类型结构，没有字段透传，因此任何前端新增的任务字段都会在后端读写一轮之后被静默丢弃。README 中「未识别的额外字段在保存时保留」只对顶层字段成立。

## 2. 目标与非目标

### 2.1 目标

1. 任务支持标签：增、删、在任务行内可见、点击即筛选。
2. 标签支持重命名（全库同名替换）与从全部任务移除。
3. 全文搜索：匹配任务正文与标签，跨分组，实时过滤。
4. 视图：分组、全部、无标签、某个标签，以及搜索态；除「分组」外一律跨分组降平展示，每行标明所属分组。
5. 视图切换入口统一在左侧栏，面板与列表两种布局共用同一套入口。
6. 标签与视图相关的筛选逻辑全部落在 `model.js` 的纯函数里，可用 `node --test` 覆盖。

### 2.2 非目标（本期不做）

- 不做标签颜色、标签分组、标签层级。
- 不做保存搜索条件或自定义智能视图。
- 不做多标签交集／并集筛选，一次只看一个标签。
- 不做模糊匹配、拼音匹配、正则匹配。
- 不做搜索历史与搜索建议。
- 不持久化当前视图与搜索词，重启回到「分组」视图。
- 不改动拖拽排序、提醒通知、多窗口等既有非目标项。

## 3. 数据模型

### 3.1 任务字段

任务新增 `tags` 字段：

```json
{
  "id": "t1",
  "groupId": "g1",
  "text": "候选列表的筛选机制有问题",
  "done": false,
  "order": 0,
  "createdAt": "2026-09-23T14:04:00.000Z",
  "updatedAt": "2026-09-23T14:04:00.000Z",
  "images": [],
  "tags": ["筛选", "评审"]
}
```

约定：

- 类型为字符串数组，缺省为空数组；数组顺序即用户的添加顺序，界面按此顺序显示。
- 单个标签在写入前去掉首尾空白；去空白后为空则忽略。输入框 `maxlength` 为 24。
- 标签名精确匹配，区分大小写，不做大小写折叠，保留用户输入的原样。
- 同一个任务内不允许重复标签，重复添加直接忽略。
- 标签的增删与图片增删同样处理：更新对应任务的 `updatedAt`。

### 3.2 数据文件版本

`CURRENT_VERSION` 由 1 升到 2，前端 `createEmptyData()` 返回的 `version` 同步改为 2。

理由：加字段本身向后兼容，旧文件缺少 `tags` 时读作空数组即可。但 1.1.0 的程序在读写新文件时会丢掉 `tags` 字段而不报错，用户看不到任何提示却已经丢数据。升版本之后，旧程序读取版本 2 的文件会明确报错并拒绝写入，损坏是可感知且可恢复的。

### 3.3 后端字段补齐

`src-tauri/src/store.rs` 的 `Task` 结构新增：

```rust
#[serde(default)]
pub tags: Vec<String>,
```

没有这一行，前端写入的标签会在下一次 `load_data` 之后消失。这是本次改动里唯一必须动 Rust 数据层的地方；`Group`、`Settings` 不变，`DataFile` 的顶层字段透传逻辑不变。

## 4. 视图模型

### 4.1 视图描述

视图是一个数据对象，不是渲染层的分支判断：

| 视图 | 描述 | 展示形态 |
| --- | --- | --- |
| 分组 | `{ kind: "group" }` | 沿用现状：面板布局显示当前分组，列表布局显示全部章节 |
| 全部 | `{ kind: "all" }` | 跨分组降平，按分组顺序排列 |
| 无标签 | `{ kind: "untagged" }` | 跨分组降平，只含没有标签的任务 |
| 标签 | `{ kind: "tag", tag: "工作" }` | 跨分组降平，只含带该标签的任务 |

搜索词 `ui.query` 是**叠加在任意视图上的筛选**，不改变视图种类。只要搜索词非空，展示形态一律降平，因为搜索的作用域是全局的。

### 4.2 展示形态的判定

降平的条件只有一条：搜索词非空，或视图不是「分组」。分组视图在两种布局下保持现有行为不变。

### 4.3 `model.js` 的接口

现有的 `DEFAULT_SETTINGS`、`createEmptyData`、`sortGroups`、`sortTasks`、`groupCounts`、`tasksForGroup`、`allTasksOrdered`、`formatStamp` 等全部保留。新增：

```js
/** 把 ui.view 归一化成视图描述；缺失或非法时回落到 { kind: "group", tag: "" } */
export function resolveView(ui)

/** 任务是否命中搜索词：匹配 text 与 tags 的子串，大小写不敏感；query 为空时恒为 true */
export function matchTask(task, query)

/** 当前视图下的可见任务，已按「分组顺序 → 组内顺序」排好并带上分组名 */
export function visibleTasks(state, view, query)

/** 每个标签的未完成任务数，返回 Map<标签名, 数量> */
export function tagCounts(state)

/** 把正文切成片段供高亮渲染：[{ text, hit }]；query 为空时返回单个非命中片段 */
export function highlight(text, query)

/** 纯函数版的批量标签改名：返回新的任务数组，不改入参 */
export function renameTagInTasks(tasks, from, to, timestamp)

/** 纯函数版的批量标签移除：返回新的任务数组，不改入参 */
export function removeTagFromTasks(tasks, from, timestamp)
```

`renameTagInTasks` 的语义：把每个任务中等于 `from` 的标签替换为 `to`；替换后同一任务内若出现重复标签则只保留一个；`to` 去空白后为空或等于 `from` 时返回入参的浅拷贝，不做任何改动。被改动的任务把 `updatedAt` 置为传入的 `timestamp`（时间由调用方提供，保持纯函数可测）。`removeTagFromTasks` 同理，只是移除而不是替换。

`visibleTasks` 的返回元素形如 `{ task, groupName }`，排序规则：先按分组的 `order`（与 `sortGroups` 一致），再按组内顺序（`sortTasks`，受 `completedBottom` 影响）。`hideCompleted` 与搜索、标签筛选叠加生效。

### 4.4 `buildView` 的输出

现有字段（`layout`、`settings`、`ui`、`groups`、`activeGroup`、`activeTasks`、`sections`、`totalUnfinished`）全部保留，语义不变。新增：

```js
{
  view,          // 归一化后的视图描述
  query,         // 当前的搜索词
  flat,          // 布尔：是否降平展示
  flatTasks,     // flat 为真时是 visibleTasks 的结果，否则为 null
  flatTitle,     // 扁平列表的标题：搜索结果 / 全部待办 / 无标签 / 标签「x」
  tags,          // [{ tag, count, active }]，按标签名排序，count 是未完成数
  viewItems,     // [{ key, label, active }]，固定视图项：全部、无标签
}
```

`flatTitle` 的取值优先级：搜索词非空时一律是「搜索结果」，否则按视图种类取「全部待办」「无标签」「标签「x」」。

渲染层只读取这些字段，不再自行判断筛选与排序。

## 5. 界面设计

### 5.1 左侧栏

面板与列表两种布局都保留左侧栏（现状即如此，宽度 214px，窄窗口 168px），视图入口统一放在这里，两种布局共用一套实现。自上而下：

1. 品牌行（现状不变）。
2. 搜索框：占满栏宽，占位文案「搜索待办」，值来自 `ui.query`。
3. 固定视图项：全部、无标签。
4. 「分组」区段：区段标题 + 现有分组项（名称 + 未完成计数），标题行右侧放「添加分组」。
5. 「标签」区段：区段标题 + 标签项（名称 + 未完成计数），按标签名排序。没有标签时不渲染这个区段，避免空噪声。
6. 底栏：只保留设置入口。原来放在底栏的「添加分组」移到分组区段的标题行。

固定视图项、分组项、标签项中，与当前视图匹配的那一项高亮；三者互斥，同时至多有一项高亮。

分组与标签两个区段共用一个滚动容器，品牌行与底栏固定不动。

### 5.2 标签项的管理

在标签项上右键弹出菜单，浮层定位在鼠标位置，含两项：

- 重命名：关闭菜单，把该标签切到内联编辑态（输入框出现在侧栏标签项位置，沿用分组重命名的既有做法），`Enter` 确认、`Esc` 取消。确认后全库同名替换。
- 从全部任务移除：第一次点击把菜单项文案改为「再点一次确认移除」，第二次点击执行。这个动作会影响多条任务，因此比照分组删除的二次确认。

点击菜单以外的任何位置或按 `Esc` 关闭菜单。

### 5.3 任务行

- 标签胶囊：显示在正文下方，点击切到该标签视图；胶囊右侧的 × 移除该任务的这个标签。开启「隐藏任务操作按钮」时只保留信息与点击筛选，不显示 ×。
- 分组徽章：只在降平展示时出现，标明任务归属的分组。
- 命中高亮：搜索时正文与标签中命中的片段用 `<mark>` 包裹。
- 标签按钮：任务行工具区新增一个标签按钮，点击在正文下方展开标签输入行；输入框内 `Enter` 添加一个标签并清空输入框、保持焦点，`Esc` 关闭输入行。文本编辑态（textarea 展开）时标签输入行同样显示在 textarea 下方。
- 标签输入行的值来自 `ui.tagDraft`，因此整棵 DOM 重建之后内容与焦点都能复原。关闭输入行时把 `ui.tagDraft` 置空，未提交的内容随之丢弃。

### 5.4 右栏

- 视图为「分组」时完全维持现状。列表布局下右栏顶部的「全部待办」标题改为「按分组」，避免与「全部」视图重名。
- 其余视图与搜索态使用新的扁平列表：单列、不分章节、每行带分组徽章与标签胶囊、命中片段高亮。行为与现有任务行一致（勾选、编辑、删除、图片、快捷键）。

### 5.5 空状态

- 某个标签或「无标签」视图下没有任务时，显示一句说明（例如「没有带这个标签的待办」），不显示分组相关的引导。
- 搜索无结果时显示「没有匹配的待办」。
- 数据里一个分组都没有时，保持现有的空状态引导不变。

## 6. 交互与快捷键

### 6.1 新增与调整的快捷键

| 按键 | 作用域 | 行为 |
| --- | --- | --- |
| `Ctrl + F` | 窗口聚焦且不在编辑态 | 聚焦搜索框并全选其中内容 |
| `Esc` | 搜索框内 | 清空搜索词并把焦点移出搜索框，视图种类不变 |
| `Enter` | 搜索框内 | 不提交、不换行，保持在搜索框内（沿用现有输入框内不响应全局快捷键的规则） |
| `Enter` | 标签输入行内 | 添加标签并清空输入框 |
| `Esc` | 标签输入行内 | 关闭输入行，放弃未提交的内容 |

其余快捷键不变。搜索框或标签输入行聚焦时，方向键归输入框自己使用，不触发任务与分组的光标移动——这一点由现有 `handleKeyDown` 里的输入框判定分支自然满足。

### 6.2 光标移动

`↑` / `↓` 的任务光标循环改为按**当前视图的可见任务列表**进行（`visibleTasks` 的结果），不再按 `activeGroupId` 过滤。否则在搜索结果或标签视图里按方向键，光标会落到看不见的任务上。

`Ctrl + N` 在降平视图下仍把新任务加进 `activeGroupId` 指向的分组；新任务带分组徽章出现在列表中，落点可见，因此不做额外提示。若当前没有分组，沿用现有逻辑自动建一个「待办」分组。

### 6.3 渲染全量重建与输入框焦点

`renderApp` 每次渲染都重建整棵 DOM（`src/app.js` 的 `host.replaceChildren`），因此新增的两个输入框同样会在每次按键后失去焦点。现有 `events.js` 的 `captureEditor` / `restoreEditor` 只识别任务编辑器与分组名输入框，需要泛化：

- 新增一份通用焦点记忆 `{ action, id, start, end }`，在 `beforeRender` 时从 `document.activeElement` 记录，在 `afterRender` 时按 `[data-action][data-id]` 找回并恢复选区。
- 只处理搜索框（`data-action="search"`）与标签输入行（`data-action="tag-editor"`）两种。
- 任务编辑器与分组名输入框沿用既有逻辑，不改动，避免回归。
- 输入框的值不由焦点记忆承担：搜索框的值来自 `ui.query`，标签输入行的值来自 `ui.tagDraft`。这样重建后的内容与状态天然一致，添加标签后清空输入框也只需要把 `tagDraft` 置空。

滚动位置的恢复沿用现有 `captureScroll` / `restoreScroll`，需要把新的滚动容器（侧栏视图区段）加入 `SCROLLABLE` 选择器。

### 6.4 输入法

搜索框在中文输入法组字期间也会触发 `input` 事件，过滤会随未确定的文本跳动。先按现状接受，不加 `compositionend` 门控；若实际体验明显干扰，再单独处理。

### 6.5 性能

搜索每键触发一次全量投影与重建。按当前数据规模（数百条）预期无感；若实测卡顿，再给 `query` 加一帧合并，不在本期实现。

## 7. 迁移与兼容

- 旧 `data.json` 没有 `tags`：前端 `normalizeData` 补空数组，后端 `serde(default)` 补空数组，不需要迁移脚本。
- 顶层未知字段的透传逻辑不变。
- `CURRENT_VERSION` 升到 2 后，版本 1 的文件读取时会出现「已按版本 2 读取」的提示，属于预期行为。
- `ui.view` 与 `ui.query` 是导航状态，不写入 `data.json`，重启回到「分组」视图。

## 8. 测试策略

### 8.1 前端单元测试（`node --test`）

`src/model.test.js` 新增：

- `resolveView`：四种合法视图原样通过；缺失、`kind` 未知、`kind: "tag"` 但标签为空时回落到分组视图。
- `matchTask`：正文命中、标签命中、大小写不敏感、空搜索词恒为真、不匹配图片路径。
- `visibleTasks`：`all` 跨分组排序正确（分组顺序优先）；`untagged` 只留无标签任务；`tag` 只留带该标签的任务；搜索词与 `hideCompleted` / `completedBottom` 叠加；返回元素带分组名。
- `tagCounts`：只统计未完成任务；同一任务内的重复标签不重复计数；没有标签的任务不贡献计数。
- `highlight`：命中在开头、结尾、中间；同一片段内的多次命中；搜索词为空；搜索词含正则元字符时按字面量处理。
- `renameTagInTasks` / `removeTagFromTasks`：不改入参；替换后同任务内去重；`to` 为空或等于 `from` 时原样返回；被改动任务的 `updatedAt` 更新，未改动的任务保持原样。

`src/theme.test.js` 不动。

### 8.2 Rust 单元测试（`cargo test`）

`src-tauri/src/store.rs` 新增：

- 带 `tags` 的数据文件往返读写后标签仍在。
- 缺少 `tags` 字段的旧文件读成空数组，且再次保存时不报错。

### 8.3 手动验收清单

1. 给任务添加两个标签，重启后仍在，顺序不变。
2. 右键标签重命名，所有带该标签的任务同步变化；重命名成一个已存在的标签名时，同任务内不出现重复。
3. 右键标签移除需要点两次；确认后所有任务上的该标签消失。
4. 点击标签胶囊切到该标签视图，点「全部」「无标签」分别得到正确结果，分组顺序与分组视图一致。
5. 搜索框输入中文与英文均能实时过滤，正文与标签都能命中，命中片段高亮；`Ctrl + F` 聚焦搜索框；`Esc` 清空并退出输入。
6. 搜索状态下方向键在可见结果内循环，勾选、编辑、删除、加图片均作用于正确的任务。
7. 面板与列表两种布局下，侧栏视图列表的切换、计数、当前项高亮一致；列表布局右栏标题为「按分组」。
8. 开启「隐藏已完成」「已完成置底」后，上述视图与搜索结果仍然一致。
9. 搜索框与标签输入行在连续输入时不丢焦点、不丢光标位置。
10. 用 1.1.0 的 exe 打开新版本产生的数据文件，得到版本过高的明确提示而不是静默丢标签。
