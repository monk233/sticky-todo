# sticky-todo 撤销实现计划

依据：[2026-09-29-undo-design.md](../specs/2026-09-29-undo-design.md)

前置：无。这一项应当排在四项的最前面：另外三项都会改动 `store.js`，而撤销的接线要碰到几乎每个动作，后做会与它们反复冲突。

完成定义：`npm test` 全绿；设计文档第 6.2 节的八项手动验证逐条通过；README 的快捷键表与功能清单更新。

## 阶段 1：纯函数与单测

`src/model.js` 新增：

```js
export const UNDO_LIMIT = 50;
export function cloneSnapshot(value);
export function pushSnapshot(stack, snapshot, limit = UNDO_LIMIT);
export function takeSnapshot(stack);
```

- `pushSnapshot` 返回新数组（不改传入的），超限时丢掉最旧的一份。
- `takeSnapshot` 返回 `{ snapshot, rest }` 或 `null`。

`src/model.test.js` 覆盖设计文档第 6.1 节的四类用例。

验证：`npm test` 通过，新增用例出现在列表里。

## 阶段 2：store 的快照栈

`src/store.js`：

1. 内部状态：`const undoStack = []`、`let applyingUndo = false`。
2. `pushUndo(label)`：`applyingUndo` 为真时返回；否则用 `cloneSnapshot` 拷出 `{ groups, tasks, activeGroupId, cursorTaskId }` 压栈。
3. `undo()`：栈空则 toast「没有可撤销的操作」并返回 `false`；否则恢复快照、清掉四个编辑态 id、`scheduleSave()`、`notify()`、toast「已撤销：<label>」。
4. `reload()` 里清空栈并置 `ui.undoLabel = ""`。
5. 返回值增加 `undo`。

验证：先在控制台手动调 `store.undo()` 走一遍（`npm run dev` 或 harness），确认恢复的是改动前的样子。

## 阶段 3：接线

按设计文档第 5 节的表逐个动作加 `pushUndo(label)`，位置一律在「确认要改」之后、真正改之前。三条纪律复述：

- `moveTask` / `moveGroup` 这类有边界 `return` 的动作，`pushUndo` 放在边界判断之后。
- `commitEdit` 里正文没变时不压栈；`removeTask` 在 `silent: true` 时不压栈。
- `toggleTask` 与它触发的 `spawnNextOccurrence` 合并为一份。

验证：对着表数一遍，确认 16 行都有对应的调用点；漏掉的用 grep 找 `data.tasks` / `data.groups` 的直接改动点做交叉检查。

## 阶段 4：界面

1. `src/events.js`：`handleKeyDown` 开头加 `Ctrl + Z` / `Cmd + Z` 分支，`ui.editingTaskId` 或到期面板聚焦时不接管；`handleClick` 加 `undo` 动作分支。
2. `src/render.js`：`renderToasts` 里给最新一条 `undo` 为真的 toast 挂 `data-action="undo"` 的按钮。
3. `src/store.js`：`undo()` 成功后，把新 toast 标成 `undo: true`（撤销完还能再撤）。
4. `src/style.css`：toast 里的按钮样式，走 `--accent` / `--accent-contrast` / `--radius-sm`。

验证：`npm test` 无回归；界面里点按钮与按快捷键行为一致。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| 漏接线某个动作，出现「撤不掉」的死角 | 对着设计文档第 5 节的表逐个打勾；用 grep 交叉检查所有直接改 `data.tasks` / `data.groups` 的位置 |
| 撤销本身也被压栈，导致原地打转 | `applyingUndo` 标志；`undo()` 内部不调任何会 `pushUndo` 的动作，直接改数据 |
| 快照太大 | 快照只含 `groups` / `tasks` / 两个 ui 字段，不含 `settings`，也不含图片文件 |
| 撤销后光标指向已不存在的任务 | 恢复 `cursorTaskId` 后校验该 id 是否在恢复后的任务列表里，不在就落到 `null` |
| 编辑正文时 `Ctrl + Z` 把整条任务撤没了 | 编辑态与到期面板聚焦时不接管该快捷键 |
| `structuredClone` 在老 WebView2 上不存在 | 只在 store 里调用；若真机上出问题，退回 `JSON.parse(JSON.stringify(...))`（数据是纯 JSON） |
| 撤销后提醒计划没跟着回退 | `scheduleSave()` 内部已经会推提醒与托盘摘要，撤销后必须调它，不能只调 `notify()` |
| 连按上移后要按很多次撤销 | 这是设计文档写明的取舍；真觉得别扭再另加按动作标签合并的规则 |
